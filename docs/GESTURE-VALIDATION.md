# 手势行为与验证

四指捏合打开，四指张开关闭。跟踪期间由手指控制透明度和缩放；只有释放后才启动收尾弹簧。停住或操作超过 5 秒不会自动完成。

松手使用当前进度与最近速度做短距离预测。打开和关闭都以 35% 行程为基础门槛，速度预测最多补偿 18% 行程；没有按接触时长区分的“快手势”规则。中途反向可以撤回，到达端点后的多余移动不会变成反向操作的空行程。

触点状态和位移在同一个锁内采样。明确的零触点立即释放；短暂的非四指帧有 75 毫秒容错，恢复时重设半径基准，保留累计进度。单纯没有新帧不代表松手。睡眠通过独立的生命周期事件取消手势。

原始触点监听不可用时，窗口内使用 NSEvent magnify 作为后备。[Apple 的 magnification 文档](https://developer.apple.com/documentation/appkit/nsevent/magnification)说明其值是每次事件的增量，因此需要累加，并区分 ended 和 cancelled。

## 自动验证

在 macOS 26.5+、Xcode 26.6+ 环境运行：

```bash
bash scripts/test-gestures.sh
```

回放直接使用生产环境的手势动画器和触点状态，验证慢速操作、停顿、反向、快速释放、最终采样、连续手势隔离、触点抖动和不同帧率下的弹簧收尾。无需辅助功能授权或真实触控板输入。

## 实机体验验证

先退出旧版 LunchPad，再启动新构建。四指手势需要该运行副本具有辅助功能权限。

1. 缓慢捏合至约半程，停住 6 秒，再继续移动：界面应保持跟随，松手后打开。
2. 从完全打开开始缓慢张开至约半程，停住后松手：界面应关闭。
3. 捏合到大半程，再反向撤回到起点附近，停住后松手：应取消打开。关闭方向同样验证。
4. 完全打开后继续捏合，再反向张开一点：界面应立即开始关闭方向的跟随。
5. 用短促但明显的捏合/张开结束：动画应接续运动；很小的误触应回到原状态。
6. 一次松手后的收尾动画尚未完成时，再开始下一次手势：界面应从当前位置接住手势。
7. 手指逐个离开、短暂增加第五指或减少一指：不应有大的缩放跳变；真正释放后应收尾。
8. 使用 F4、Dock 图标和 Esc 连续开关，再做手势：应保持正确开关状态。

自动回放验证逻辑和数值稳定性；真实触控板的触点质量、手指距离及主观跟手感仍需这一步确认。上述参数是本项目的交互设计值，不声称是 Apple Launchpad 的内部参数。

设置中的诊断日志会记录 `release progress=... velocity=... target=...`。如果某次结果不符合预期，可据此核对松手位置、方向和最终目标。
